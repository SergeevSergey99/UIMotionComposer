# UI Motion Composer

Work within `Assets/Plugins/UIMotionComposer` and preserve the asset as a reusable package rather than coupling it to GuildMaster game code.

## Architecture

- Runtime code is in `Scripts/Runtime` under the `UIMotionComposer` namespace and the `UIMotionComposer.Runtime` assembly.
- Editor tooling is in `Scripts/Editor` under `UIMotionComposer.Editor`; tests are in `Tests/Editor`.
- `TweenPlayer` owns local animation definitions, playback state, Initial Pose, and scene-object target bindings.
- `TweenAnimationAsset` is a reusable ScriptableObject containing clips. It must not serialize scene references. Use named target slots and resolve them on the local `TweenPlayer`.
- Clip lists use `[SerializeReference]` and `BaseTweenClip` subclasses. Preserve managed-reference types and check scene/preset YAML for missing clip types after serialization changes.
- Runtime playback uses the asset's own evaluator and runner. Do not assume DOTween lifecycle APIs control it.
- The old V1/V2 split has been removed. Do not introduce `V2` namespaces, menu names, migration paths, or duplicate systems.

## Inspector conventions

Prefer Unity's serialized UI and native property controls.

- When one field needs special presentation or actions, introduce a focused serializable wrapper and a `CustomPropertyDrawer` for that wrapper or value type.
- Draw editable values through `EditorGUI.PropertyField` so colors, vectors, object references, enums, curves, and UnityEvents retain standard Unity behavior.
- Do not replace an entire component inspector merely to customize one section. A component `CustomEditor` is appropriate only for coordination that spans fields, such as Timeline selection, preview lifetime, validation, or animation-level commands.
- Keep runtime data independent of editor-only display state.
- Editor mutations must use `SerializedObject`/`SerializedProperty`, support Undo, mark objects dirty, record prefab-instance modifications when applicable, and invalidate preview/authoring caches.
- Preview must not permanently dirty transforms or fire side-effect clips. Stop and restore preview on selection, focus, play-mode, undo, and assembly-reload boundaries.

## Behavioral invariants

- `Initial` means the serialized authored pose, not whichever value happens to exist on first playback when a pose has been captured.
- Rebuild driven UI layouts before capturing Initial Pose.
- Runtime and preview sampling must agree.
- Resolve conflicts per target property binding, not per animation as a whole.
- Hover child loops must be stoppable by state transitions; nested animation playback must preserve `Fire And Forget`, `Wait`, and `Link Lifetime` semantics.
- Shared presets expose target slots; local components supply scene or prefab objects.

## Showcase and presets

- Treat `Scripts/Editor/TweenDemoSceneBuilder.cs` as the source of truth for `Examples/Showcase/UIMotionComposerShowcase.unity`. Rebuild the scene through the builder instead of hand-editing generated YAML.
- Keep showcase layout responsive using Unity layout components and layout-owned cells. Animated transforms belong below the objects whose size is controlled by a layout group.
- Keep an enabled orthographic object tagged `MainCamera` in the showcase so opening it does not display the no-camera warning.
- Presets are generated by `TweenPresetLibrary`. Unity may regenerate only managed-reference `rid` values when rebuilding them. Inspect preset diffs and do not retain identifier-only churn.

For a showcase change, run the static entry point:

```text
-batchmode -quit -projectPath <project-root> -executeMethod UIMotionComposer.Editor.TweenDemoSceneBuilder.BuildAndValidateFromCli -logFile <temporary-log>
```

For runtime or editor changes, also run EditMode tests:

```text
-batchmode -projectPath <project-root> -runTests -testPlatform EditMode -testFilter UIMotionComposer.Tests -testResults <temporary-xml> -logFile <temporary-log>
```

The Unity launcher may return before the worker exits. Confirm completion from the log or test XML, including the Unity return code, and do not leave logs or test results under `Assets`.

Before handing off, inspect `git diff --check`, missing scripts/types, and unrelated generated changes. Preserve pre-existing user modifications.
